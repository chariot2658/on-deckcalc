# 活動配隊計算機（BanG Dream! Our Notes）

根據最新的活動資料和你持有的卡片，找出活動點數（或活動道具）最多的配隊。

本專案為非官方愛好者專案，與遊戲的開發和營運方無關。倉庫不包含任何遊戲資源：卡面縮圖、masterdata 和譜面資料都是開啟時從下方「資料來源」下載。

## 使用方式

1. 開啟 <https://chariot2658.github.io/on-deckcalc/>。
   也可以在本機執行：雙擊 `start.cmd`（需要 Python），瀏覽器會開啟 <http://localhost:8765/>。
   兩個網址的卡片清單各自分開存，要搬的話用「設定」的「匯出 JSON」／「匯入 JSON 檔」。
2. 登錄持有的卡片，有三種方式：
   - 「截圖匯入」：選擇遊戲裡「團員名單」「快照清單」畫面的截圖（可多張、拖曳或 Ctrl+V 貼上）。檢查辨識結果後按「套用」。
   - 「設定」→「載入從截圖辨識的清單」。
   - 在「成員卡」「快照」分頁點圖片，手動登錄。

   特訓次數、覺醒、開放上限、演出技能和激奏技能等級在清單畫面上看不到，匯入後要到「成員卡」「快照」分頁調整（技能等級預設 1）。
   匯入時勾「等級直接設成上限」，等級會設成目前特訓／開放上限能升到的最高等（特訓、開放上限只依截圖上的等級推到最低需要的值），
   適合先排出最佳隊伍再去升級。這個選項會記住。
3. 「計算」分頁選模式（一般 Live／挑戰 Live）、遊玩方式（單人／多人激奏）、能穩定打的最高等級，
   再填平常的準度：Perfect 率（結算畫面 PERFECT ÷ 全部判定）和每場斷 combo 幾次（MISS＋BAD，GOOD 不會斷 combo），按「計算最佳配隊」。
   歌曲會自動選好。結果下方的「歌曲比較」列出每首歌各自配出最佳隊伍後的收益，可以切換「每場」「每分鐘」排序，點一列看那首歌的隊伍。
4. 用推薦的隊伍打一場後，可以在結果卡片下方填入遊戲顯示的綜合力，校正綜合力模型（角色等級等都填好時不需要）。

卡片清單只存在你的瀏覽器裡，不會上傳。換電腦或瀏覽器時，用「設定」的「匯出 JSON」／「匯入 JSON 檔」搬過去。

清除瀏覽資料、用無痕視窗，或 iPhone／iPad 的 Safari 7 天沒開這個網站時，清單可能消失，請定期匯出備份。
工具會請瀏覽器長期保留資料（Chrome、Edge 通常會同意，「設定」頁會顯示結果）。修改後超過一天沒匯出時，「設定」分頁會出現 ● 提醒。

## 資料來源

| 資料 | 來源 | 更新時機 |
|---|---|---|
| masterdata（活動、卡片、加成、評級門檻…） | [StarMoe-org/moenotes-masterdata](https://github.com/StarMoe-org/moenotes-masterdata) | 每次開啟時檢查版本，有新版就重新下載 |
| 譜面的「每點綜合力分數」、演出技能權重與激奏資料 | nnnotes 的 `music-data.json`（storage.bdon.moe） | 每天一次，或按「更新資料」 |
| 整場模擬（ournotes-deck 的 WASM 引擎與譜面資料，約 5 MB） | `music-data.json` 指向的 replay 資料（storage.bdon.moe） | 第一次模擬時下載，版本變了才重新下載 |
| 卡面縮圖 | assets.bdon.moe | 瀏覽器快取 |

## 計算方式

- **綜合力**：移植自 [ournotes-deck](https://github.com/empty-sekai/ournotes-deck)，它按遊戲客戶端的算式逐項計算：等級、特訓、覺醒、快照開放上限、角色等級、強化樂團（樂團道具）、快照、屬性連結、歌曲屬性與標籤、隊長技能、T.G.W CARD（VIP）。
  - 角色等級、強化樂團道具等級與 T.G.W CARD 等級在「設定」頁填寫。三項都填好時模型與遊戲顯示的綜合力完全一致（實測 378,423），「綜合力校正」維持 1.000 即可；有沒填的加成時再用校正補上。
  - 活動的「數值」加成在挑戰 Live 會計入綜合力和分數（實測 244,053 完全一致），一般 Live 不計入；設定裡可以讓一般 Live 也計入。
- **分數**（搜尋用）＝ 綜合力 ×（該譜面的「每點綜合力分數」＋ 演出技能的期望加分）× 準度係數。
  - 演出技能用 `music-data.json` 的技能權重計算：每種技能效果在每個發動位置的加分，都是 ournotes-deck 用整場模擬量出來的。
  - 遊戲每場開始時隨機打亂發動順序（solo 重試時順序不變），所以搜尋取 5 個位置的平均。
  - 快照技能（延長演出技能時間、GREAT 轉 PERFECT、回復 LIFE）不在搜尋的估計裡，結果的「模擬分數」才會算進去。
- **模擬分數**：結果卡片上的隊伍會再交給 [ournotes-deck](https://github.com/empty-sekai/ournotes-deck) 的整場模擬（WASM，nnnotes 發布在 music-data 旁邊）。它照遊戲客戶端的邏輯逐幀計算，包含演出技能和快照技能，條件是全 Perfect；單人不開激奏，多人開激奏（見下方「激奏」）。
  - 工具列出 120 種發動順序的分數範圍，以及有多少比例的順序能達到各評級。
  - 實測（夢現妄想世界 EXPERT，綜合力 378,468）：模擬平均 1,767,907，遊戲最高分 1,767,821 落在範圍內。
- **準度**：分數損失幾乎都來自斷 combo，不是 Great。
  - combo 加成每 10 combo +1%（100 combo 以後每 10 combo +0.5%），500 combo 時達到上限 +30%。斷 combo 後要從 0 重新累積。
  - 在 833 顆的譜面上，曲子中段斷一次 combo 約少 6～7%，開頭或結尾斷只少 0.1%。11 個 Great 只少 0.3%（Great 是 Perfect 的 80%）。
  - 有斷 combo 時，搜尋算出每支隊伍在每首歌拿到各評級的機率（依斷的位置分布），用機率加權的期望收益排名。
    餘裕很小、可能掉一級的隊伍會排在穩定拿到評級的隊伍後面；結果卡片會列出各評級的機率，pt／道具／CP 是期望值。
  - 模擬分數的評級機率同時考慮發動順序和斷 combo 的位置。
  - 實測 IMG_0045（98.4% Perfect、1 Miss）：1,637,627 落在工具顯示的範圍 1,636,073～1,776,967 內。
- **活動點數** = 評級點數 × 加成道具倍率 × (1 + 成員卡的點數加成)；**活動道具** = 評級道具數 × 倍率 × (1 + 快照的道具加成)。這兩條公式已用遊戲結算畫面驗證。
- **CP**：一般 Live 結算時會拿到 CP，數量 = 評級對應的 CP（D 3、C 4、B 5、A 6、S 8、SS 10）× 加成道具倍率，**不吃卡片加成**（已用結算畫面驗證：C、3 個加成道具 → 60 CP）。挑戰 Live 每 1 CP 可換「挑戰評級點數 × (1+加成) ÷ 200」pt，消耗 200／400／800／1600 CP 時，每 CP 換到的點數都一樣。所以用「活動點數」優先計算一般 Live 時，工具會先找出最佳挑戰隊，再把各隊拿到的 CP 換算成 pt 一起排名。結果就是先比評級，同評級再比加成。
- **多人（激奏）**：活動點數、道具和 CP 看的是**房間評級**（結算畫面右上角的大徽章），不是自己分數的評級（SCORE 旁邊的小徽章）。房間評級＝全房總分對照該曲的多人門檻，門檻 = 曲目的多人基準分 × √(5 × 人數)，5 人房就是基準分 × 5（已用結算畫面驗證：自己 C、房間 B → 1050 pt／1738 道具／75 CP）。
  工具用「自己的預估分數＋其他玩家平均分數 ×（人數 − 1）」估算房間評級。其他玩家的分數通常佔大部分，所以多人時加成高的隊伍往往比綜合力高的隊伍划算。挑戰 Live 一律當單人計算。
- **激奏**（只有多人才有）：譜面的三段 Fever 變成激奏區間，各有一個任務（連擊、幸運或 JUST，依歌曲而定）。
  - JUST 任務的區間裡可以打出 JUST（一顆音符算 230%，PERFECT 是 100%）；每段結束時依自己在房間裡該任務的名次，加上該段分數的一定比例（第 1 名 +250%～+370%，第 4、5 名 +100%～+170%，依歌曲）。
  - 成員卡的**激奏技能**和快照的**激奏技能**（支援）只在這時發動，只在同任務的區間裡有效，與發動順序無關。
  - 遊戲同時算兩個分數：含激奏的分數，以及完全不含激奏的分數（存成最高分、結算畫面大字顯示的 SCORE）。房間評級用的是含激奏的分數：多人的基準分是單人門檻的 2 倍以上，只有含激奏的分數才可能達到（例如 TearJerker 5 人房 B 要 2,064 萬，平均每人 413 萬）。這是從門檻推論的，遊戲客戶端看不到伺服器怎麼用。
  - 多人時工具用含激奏的分數。計算條件要填「激奏每段的名次」（三段都假設同一名次，房間人數以內）和「JUST 區間的 JUST 率」。基本分數與演出技能權重來自 `music-data.json` 的開激奏資料，名次的換算是精確的；JUST 率在 0% 與 100% 之間線性內插（誤差約 0.2%）。
  - 搜尋裡的激奏技能：用 `music-data.json` 量好的「該技能單獨滿級時」的加分。未滿級的等級改的是發動條件或時間，所以第一次多人計算時會用整場模擬在幾首歌上量出「該等級 ÷ 滿級」的比例（每種技能約 0.05 秒）。幾個技能的加分直接相加，是近似值；幸運類技能受亂數影響。
  - 模擬分數在多人時開激奏：JUST 區間依 JUST 率平均分配 JUST，三段固定在指定名次，成員的激奏技能和快照的激奏技能都逐格計算。幸運區間的抽選依亂數種子，模擬用第一個種子，再依 `music-data.json` 公開的各種子平均分數修正。
- **搜尋**：列舉所有「5 位不同角色」的成員組合，逐一試每位當隊長，再用動態規劃分配快照。它會在不掉評級的前提下，把點數與道具加成拉到最高。
- **選歌**：活動點數只看評級和加成，不看分數多寡，所以最好的歌是用你的隊伍能衝到最高評級的那首，也就是評級門檻相對於可得分數最低的歌（例如焚音打的 B 門檻特別低）。
  「歌曲比較」的「每場」就是每用一次 LB 的收益；「每分鐘」＝每場 ÷（歌曲長度＋每場額外時間），歌曲長度來自 `music-data.json`，額外時間（載入、結算）預設 40 秒，可以自己改。
  LB 會用完時看「每場」，時間有限、LB 用不完時看「每分鐘」。餘裕很小的歌，實際打可能掉一級。
  計算條件的「選歌」可以改成「每分鐘收益最高」：推薦的隊伍和歌曲改用每分鐘收益挑選，會避開焚音打這類長歌，必要時寧可拿低一級的評級。

## 截圖辨識（recognize.js）

全部在瀏覽器裡執行，不用安裝其他東西，截圖也不會上傳。

1. **找格子**：先把每一欄的邊緣數量投影到 X 軸，擬合出等間距的欄。列的範圍則看卡片左右邊框出現在哪些高度，這樣卡片上方的「♪ 20%」徽章才不會干擾判斷。從寬高比可以判斷是成員卡（3:4）還是快照（16:9）。被畫面切到一半的卡會略過。
2. **認卡**：把卡面縮成 12×16 或 16×9 的色塊，和每張官方縮圖比較。屬性圖示、「!」、徽章和等級字所在的位置不列入比較。
   - 遊戲裡的成員卡顯示的是縮圖上半部放大後的樣子，這個裁切範圍已經先量好。
   - 距離夠小、而且和第二名差距夠大的才算確定，其餘標成「請確認是哪一張」。
3. **讀等級**：先找出「Lv.NN」的白色字形，再把每個數字和模板比對。模板來源有兩個：從截圖取樣的遊戲字形，以及 Arial、Segoe UI、Malgun Gothic 的數字，後者用來補齊截圖裡還沒出現過的數字。封閉孔洞的數量用來區分 5/6、0/8 這類容易混淆的數字。沒把握的等級會標成「請確認」。

測試結果（4 張清單截圖，外加縮成 1/2、1/3、JPEG 壓縮、裁切的變體）：

- 卡片 ID 全部正確。
- 等級 222 格中 220 格正確，另外 2 格標成「請確認」，沒有任何讀錯卻沒被標出來的情況。
- 結算畫面等其他畫面不會被誤認成卡片。

## 限制

- 斷 combo 的損失假設每顆音符權重相同，沒考慮技能時段；斷在技能密集的段落會比估計多少約 1%。
- 搜尋的評級機率只考慮斷 combo 的位置，沒考慮發動順序和快照技能（模擬那一行才有），兩者可能差幾 %。
- 激奏的名次要自己假設（三段同一名次）。實際名次取決於同房其他玩家各任務的表現，工具無法預測，所以多人的分數只是在該名次下的估計。
- 演出技能和激奏技能等級要自己在「成員卡」分頁設定，預設 1。
- 新歌如果還沒有計分資料（music-data.json 尚未收錄），就不會出現在推薦裡。
- 模型結果只是預估。建議先用推薦隊伍打一場，確認評級。

## 開發

沒有建置步驟，也沒有 npm 套件。測試要用 Node.js，並且需要在 deckcalc 的上一層準備兩份資料：

```sh
cd ..                                   # deckcalc 的上一層
git clone --depth 1 https://github.com/StarMoe-org/moenotes-masterdata.git
mkdir data
curl -o data/music-data.json https://storage.bdon.moe/moenotes/music-data/music-data.json
cd deckcalc
```

```sh
node test/power.test.js    # 綜合力模型 vs 截圖
node test/search.test.js   # 搜尋與活動點數公式
node test/fetch-replay.js  # 下載模擬用的 WASM 引擎與譜面資料到 ../data/replay/
node test/skills.test.js   # 演出技能估計與整場模擬 vs 結算畫面
node test/gekisou.test.js  # 多人激奏：開激奏的分數、名次、JUST 率、激奏技能 vs 整場模擬
```

檔案：`engine.js`（計算核心，瀏覽器與 Node 共用）、`data.js`（下載與快取）、`worker.js`（背景搜尋與模擬）、
`simulate.js`（呼叫 ournotes-deck 的 WASM 做整場模擬，瀏覽器與 Node 共用）、
`recognize.js`（截圖辨識，瀏覽器與 Node 共用，輸入是 `{width, height, data}` RGBA）、`app.js`（介面）。
